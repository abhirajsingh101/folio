Order-path cutover

Move order writes from the shared orders schema to the extracted instance, and prove it took.

Stop

Do not run this during a peak-season window (2026.11.24 – 2027.01.06) or while reconciliation is reporting a non-zero divergence. Both are grounds to stop and reschedule, not to proceed carefully. If the divergence appeared in the last hour, page the on-call database owner before doing anything else.

SECTION 01Preconditions

Every line is a check with a value you can read, not a note. If one fails, stop and page the on-call lead — the cutover keeps until tomorrow.

  • Reconciliation clean for 7 consecutive days (recon report --since 7d, divergence 0).
  • Dual-write lag under 2 seconds at p99 for the last hour.
  • Both rehearsals signed off, most recent within 14 days.
  • Base backup of both instances verified in the last 6 hours.
  • Incident channel open, on-call lead and database owner present.

Access required

Role orders-cutover on both instances, and the deploy pipeline. Request it in the incident channel — do not escalate your own access, and do not run this with a role borrowed from someone not on the call.

SECTION 02Procedure

  1. Announce the start. Post in the incident channel naming this document and revision. Expect: acknowledgement from the on-call lead before continuing.
  2. Freeze schema changes. deploy gate set orders-schema --closed. Expect: the gate shows closed and any queued migration reports as blocked.
  3. Drain the writer queue. svc pause order-writer, then watch svc queue order-writer. Expect: depth reaches zero within 90 seconds. If it does not, resume and stop here.
  4. Confirm the final reconciliation. recon report --now. Expect: divergence 0 across all 41 tables. This is the last checkpoint before the switch.
  5. Switch the read path. deploy config set orders.reader=extracted. Expect: read error rate flat for 5 minutes at baseline.
  6. Switch the write path. deploy config set orders.writer=extracted, then svc resume order-writer. Expect: writes land on the extracted instance and the old instance's write counter stops climbing.
  7. Lift the schema gate and announce completion with the measured values from section 03.
Reversible

Dual-write stays on for 14 days after the cutover, so steps 5 and 6 are switches, not a migration. Reversing is the same two commands with =shared, in the reverse order, and takes about four minutes.

SECTION 03Verification and rollback

Record the measured value, not a tick. A column of ticks is not evidence that the order path recovered, and it is what the post-incident review asks for.

If a check fails

Rollback

Reverse steps 6 then 5 with =shared, resume the writer, and announce the rollback with the failing value. Do not attempt a partial state — a reader on one instance and a writer on the other passes every check above and corrupts quietly. Raise an incident and hand back to the database owner.

After the cutover

  • File the measured table in the change record within 24 hours.
  • Leave dual-write on for 14 days; retiring it is SOP-043.
  • Raise a revision here if any step read wrong on the night.
